# 제품 의사결정 기록장

**결론과 함께 결정 이유·대안·변경 배경을 다음 기획과 구현에서도 찾습니다.**
대상은 PM·기획자·개발 리더입니다. 주간 기획 검토에서 과거 결정을 확인하고 새 판단을 기록합니다.

## 첫 체험

[공통 설치](../README.md)를 마친 뒤 저장소 루트에서 실행합니다.

```bash
.venv-workflows/bin/python examples/workflows/demo.py --workflow decisions
```

제품 문서 `product/` 범위에서 검색합니다. 같은 단어가 있는 코드·운영 문서와 구분하되
제안·철회·이전 정책을 함께 검색합니다. `free_trial` 결과에서 7일의 이전 정책,
14일의 채택 결정, 30일의 제안을 비교합니다.
`audit_retention` 결과는 서로 충돌하는 두 채택 기록입니다. 어느 쪽도 임의로 확정하면 안 됩니다.
검색 순위, 파일 수정 시각, 숫자의 크기는 결정의 권위가 아닙니다.

## 기록하고 다시 쓰기

1. 회의 메모·기획 문서·이슈에서 필요한 내용을 [결정 양식](template.md)으로 정리합니다.
2. 업무 담당자가 결정 여부와 적용 범위를 확인합니다. 기억 저장 승인은 업무상 채택 승인과 다릅니다.
3. 문서를 저장·색인하고, 다음 검토에서 주제 식별어와 대체 문서를 함께 찾습니다.
4. 변경 시 새 문서를 만들고 이전 문서에 `대체됨`과 후속 링크를 기록합니다.
   새 문서에는 이전 문서 링크를 넣고 두 파일 모두 재색인합니다. 이전 근거는 보존합니다.

```text
memtomem에서 [주제 식별어]의 결정과 관련 근거를 검색하세요.
각 원문의 결정일, 상태, 적용 범위, 채택 확인자, 대체 관계를 확인하세요.
현재 확인 가능한 결정, 이유, 검토한 대안, 원문 경로를 정리하세요.
제안·철회를 채택으로 취급하지 마세요. 채택 문서가 충돌하면 둘 다 인용하고 미확인으로 남기세요.
근거가 없으면 이유를 만들어내지 말고 확인할 질문을 적으세요. 새 기억 저장은 초안 검토 뒤에 합니다.
```

원문을 찾는 기본 체험은 LLM 없이 가능합니다. 위 프롬프트에 따른 해석은 연결한 AI 도구에서
별도 평가합니다. 녹취·이슈 자동 연동과 업무 승인 시스템은 이번 패키지에 없습니다.

## 평가자가 확인할 것

| 상황 | 기대 해석 |
|---|---|
| free_trial 이전·채택·제안 | TRIAL-002의 14일이 현재 채택; 7일은 대체됨, 30일은 제안 |
| mobile_offline 제안만 존재 | 출시 일정 확정 불가 |
| csv_export 철회 | 자동 이메일 발송 정책으로 적용 불가 |
| audit_retention 채택 기록 충돌 | 90일·180일 중 임의 선택하지 않고 담당자 확인 |
| enterprise_refund_basis 자료 없음 | 색인·검색 범위를 확인한 뒤 근거 미확인으로 보고 |

[evaluation.json](../evaluation.json)의 `decisions` 10개 과제에는 기대 출처와 사람용 판단 기준이
있습니다. 자동 검색 검증 통과만으로 위 해석까지 통과했다고 표시하지 않습니다.
PM이나 개발 리더가 검토된 결정 묶음과 이 안내를 동료에게 전달해 파일럿을 시작할 수 있습니다.
