# 2주 파일럿 운영 안내

목표는 설치 수보다 **자기 자료를 다음 주의 실제 업무에 다시 사용하는 사람**을 확인하는 것입니다.
아래 수치는 초기 의사결정 기준이며 관측 성과가 아닙니다. 현재 사용자 모집·실험은 수행하지 않았습니다.

## 모집과 진행

1. 개발 인계 패키지로 공통 체험을 점검하고 의사결정·온보딩 순서로 패키지를 준비합니다.
2. 패키지별 대상 사용자 10명을 모집합니다. 인계는 개발자 모임, 의사결정은 PM·개발 리더,
   온보딩은 프로젝트 유지보수자와 신규 기여자가 초기 모집 경로입니다. 실제 연락·초대는 운영자가 진행합니다.
3. 참가자에게 임의 참여 ID를 부여합니다. 여러 패키지에 참여해도 전체 사용자 수에는 한 번만 집계합니다.
4. 1주 차에 샘플→자기 자료 순서로 체험합니다. 설치 시간과 자료 준비 시간은 업무 수행 시간과 분리합니다.
5. 2주 차에는 운영자가 정답을 안내하지 않는 실제 후속 작업에서 재사용 여부를 기록합니다.
6. 종료 시 [참가자 일지](participant-log.md), [평가자 기록](reviewer-scorecard.md)을 모아 판단합니다.

팀 자료에 접근할 권한이 있는 참가자만 참여합니다. 제출 일지에는 고객 원문·대화·코드나
개인 메모를 넣지 않고 자료 개수, 시간, 성공 여부, 익명화한 오류 유형만 적습니다.
출처 확인은 참가자의 로컬 환경에서 진행하고 결과만 기록합니다. 자동 원격 수집은 없습니다.

## 측정 정의

| 지표 | 분모·계산 | 초기 기준 |
|---|---|---|
| 자기 자료 첫 성공 | 모집한 10명 중 자기 문서를 색인·검색·원문 확인한 인원 | 7명 이상 |
| 2주 차 재사용 | 모집한 10명 중 자신의 이전 자료를 실제 업무 결과에 활용한 인원 | 4명 이상 |
| 업무 시간 절감 | 각 유효 짝의 `(기존 시간 - 패키지 시간) / 기존 시간` 중앙값 | 30% 이상 |
| 출처 연결 | 패키지별 evaluation.json 10개 과제; 원문 ID·경로 대조 | 오류 0건 |
| 의사결정 해석 | 제안·대체·철회·충돌·근거 없음 사례를 사람이 판정 | 잘못된 확정 0건 |
| 수정·범위 | 재색인 후 새 내용 확인, 다른 저장소 유출 없음 | 자동 검증 통과 |

재사용에는 데모 재실행·단순 앱 실행·같은 과제 반복을 포함하지 않습니다.
미응답·중도 이탈은 성공으로 세지 않고 모집 분모 10명에 남깁니다.

시간 비교는 같은 난도의 서로 다른 과제 A/B를 사용하고, 참가자 절반은 기존 방식→패키지,
나머지는 패키지→기존 방식 순서로 수행합니다. 정답을 이미 본 과제의 반복은 비교에서 제외합니다.
두 방식 모두 정확하게 완료하고 기존 시간이 0보다 큰 짝만 시간 절감 계산에 포함합니다.
유효 짝이 5명 미만이면 시간 효과는 **판단 유보**로 남기고 후속 모집합니다.
설정 실패·잘못된 결과·누락도 별도 집계해 빠르지만 틀린 결과가 좋은 성과로 보이지 않게 합니다.

## 선택과 후속 투자

기준 통과 여부와 원시 인원수를 함께 보고합니다. 소규모 편의 표본이므로 시장 수요나
일반적인 생산성 개선으로 확대 해석하지 않습니다.
통과 후보 중 **2주 차 재사용률 → 시간 절감 → 첫 성공률** 순으로 후속 투자 대상을 고릅니다.
모두 동률이면 기존 우선순위(인계→의사결정→온보딩)를 따릅니다.
일부 지표가 미측정이면 통과로 처리하지 않습니다. 모두 미달이면 사용 상황·자료 준비 부담을 수정해 다시 시험합니다.
동료 추천 인원과 실제 신규 유입 인원은 별도로 기록하며 설치 수와 혼합하지 않습니다.

## 과제 평가

[evaluation.json](../evaluation.json)의 각 항목에 질문, 기대 출처·본문, 사람용 해석 기준이 있습니다.
평가 파일과 빈 양식은 검색 대상에서 제외합니다. 자동 검증은 검색 결과의 출처·본문을 확인할 뿐,
AI의 해석을 채점하지 않습니다. AI를 연결했다면 모델·설정·세션·원문 확인 결과를 평가자 기록에 적으세요.
CLI와 MCP 결과는 별도 기록합니다. 실제 AI 동작을 확인하지 않았으면 미실행으로 표시합니다.
