# 개발 작업 이어가기

**내가 진행하던 작업을 새 세션이나 다른 AI 도구에서 이어갑니다.**
처음 보는 프로젝트를 이해하려면 [온보딩 패키지](../onboarding/README.md)를 사용하세요.

## 첫 체험

[공통 설치](../README.md)를 마친 뒤 저장소 루트에서 실행합니다.

```bash
.venv-workflows/bin/python examples/workflows/demo.py --workflow handoff
```

`worker lease recovery`의 인계 기록에서 다음 작업 `TASK-JOBS-88`과 checkpoint 확인 순서를
찾습니다. 이어서 `billing webhook retry`의 다음 작업을 확인합니다. 원문에서 확정한 사실과
아직 수행하지 않은 일을 구분하세요. 합성 인계 기록은 실제 테스트를 통과했다는 증거가 아닙니다.

## 내 프로젝트에서 쓰기

1. 작업을 마칠 때 [인계 양식](template.md)을 채웁니다. 원문 경로, 관찰한 revision,
   실제 실행한 검사와 결과, 미실행 항목을 적습니다.
2. 해당 파일을 명시적으로 저장·색인합니다. 대화 전체를 자동 저장하지 않습니다.
3. 새 세션에서 아래 프롬프트로 기록을 찾고 실제 Git 상태와 대조합니다.
4. 완료한 작업과 다음 행동을 갱신하고 재색인합니다.

```text
memtomem에서 [주제 식별어]에 대한 인계 기록을 검색하고 원문 경로를 보여주세요.
완료한 작업, 실제 검증 결과, 미실행 검사, 다음 행동을 나눠 정리하세요.
저장된 프로젝트 경로·revision과 현재 Git 상태를 비교하세요.
차이가 있으면 먼저 설명하고, 기록만으로 변경이나 테스트 통과를 단정하지 마세요.
```

실제 런타임 간 저장·재개에는 [기존 handoff 기능](../../../docs/guides/integrations/cross-runtime-handoff.md)을
사용합니다. 동일한 신뢰 사용자와 순차 세션을 위한 기능이며 동시 작업 조정기가 아닙니다.

## 성공 확인

새 CLI 프로세스 검색과 실제 AI의 새 세션 검색을 별도로 기록합니다.
AI에서는 원문과 도구 호출 결과를 확인하고, 기록된 검사와 현재 검사 결과를 구분해야 합니다.
[evaluation.json](../evaluation.json)의 `handoff` 과제 10개로 출처를 확인한 뒤
[사용 일지](../pilot/participant-log.md)에 자기 자료 재사용을 기록합니다.
개발자 모임에서는 작업 종료→새 세션 재개 순서로 시연합니다.
