# Slateharbor 인증: 장애 회고

> 합성 프로젝트 기록. 상태: current. 기준일: 2026-08-24. 실제 운영 지침이 아닙니다.

## legacy callback

관찰 (2026-07-11 09:10 KST): INC-AUTH-17에서 신규 웹 로그인은 정상인데 구형 데스크톱만 callback 404가 발생했다. 웹 성공률 대시보드에는 장애가 드러나지 않았다.

09:25 진단: 구형 클라이언트 cohort의 callback 404를 확인하고 legacy route를 유지한다. V2 문제는 AUTH_CALLBACK_V2_ENABLED를 false로 되돌려 분리한다.

10:05 즉시 완화: `legacy callback`의 `legacy_callback`를 이전 `False`에서 `True`로 조정한 canary를 비교했습니다. 재발 빈도와 영향 범위를 줄이기 위한 조치이며, 이것만으로 원인이 사라졌다고 보지 않습니다. 확정된 정책 계약은 아래 배운 점과 채택 결정에 있습니다.

후속 작업: TASK-AUTH-42: 데스크톱 cohort별 사용량 관찰을 추가한다. 삭제 PR은 아직 승인되지 않았다.

배운 점: 데스크톱 2.8 클라이언트가 /api/auth/legacy-callback을 계속 호출한다. AUTH_CALLBACK_V2_ENABLED만으로 구형 경로를 제거하면 재로그인이 불가능하다. [채택 결정](../decisions/decision-current.md).

## session expiry

관찰 (2026-07-12 09:10 KST): 교대 종료 후 같은 브라우저를 쓰던 다른 직원에게 이전 tenant 화면이 노출됐다.

09:25 진단: idle 시간과 전체 세션 나이를 각각 확인하고 만료 시 재인증한다.

10:05 즉시 완화: `session expiry`의 `session_minutes`를 이전 `120`에서 `60`로 조정한 canary를 비교했습니다. 재발 빈도와 영향 범위를 줄이기 위한 조치이며, 이것만으로 원인이 사라졌다고 보지 않습니다. 확정된 정책 계약은 아래 배운 점과 채택 결정에 있습니다.

후속 작업: TASK-AUTH-43: session age 경계값을 프런트 안내 문구와 맞춘다.

배운 점: 공용 단말에서 열린 세션이 다음 교대조까지 남지 않게 한다. 개인 기기의 refresh token 정책과 혼동하지 않는다. [채택 결정](../decisions/decision-current.md).

09:25 진단: 계정과 시간창을 함께 확인하고 IP 전체 차단을 피한다.

10:05 즉시 완화: `login throttle`의 `login_attempts`를 이전 `10`에서 `5`로 조정한 canary를 비교했습니다. 재발 빈도와 영향 범위를 줄이기 위한 조치이며, 이것만으로 원인이 사라졌다고 보지 않습니다. 확정된 정책 계약은 아래 배운 점과 채택 결정에 있습니다.

후속 작업: TASK-AUTH-44: 계정별 throttle 로그에 원인 코드를 추가한다.

배운 점: 계정 단위 공격을 늦추되 회사 NAT 뒤의 다른 사용자를 함께 차단하지 않는다. [채택 결정](../decisions/decision-current.md).

## recovery inventory

09:25 진단: 남은 코드 수 분포와 재발급 요청 건수를 함께 확인한다. 소진이 가까운 사용자에게 재발급을 먼저 안내한다.

10:05 즉시 완화: `recovery inventory`의 `recovery_codes`를 이전 `4`에서 `8`로 조정한 canary를 비교했습니다. 재발 빈도와 영향 범위를 줄이기 위한 조치이며, 이것만으로 원인이 사라졌다고 보지 않습니다. 확정된 정책 계약은 아래 배운 점과 채택 결정에 있습니다.

후속 작업: TASK-AUTH-47: 남은 코드 수가 임계값 아래로 내려가면 재발급을 안내하는 경고를 추가한다.

배운 점: 복구 코드는 한 번만 쓰며 재발급 시 기존 묶음을 모두 폐기한다. 한 묶음은 8개로 발급해 소진으로 인한 잠금을 줄인다. [채택 결정](../decisions/decision-current.md).
