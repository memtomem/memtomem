## billing webhook retry

관찰 (2026-07-11 09:10 KST): INC-BILL-09에서 공급자 timeout 뒤 재전송을 신규 청구로 처리해 중복 원장이 생겼다.

09:25 진단: provider event ID로 중복 수신을 확인하고 settlement 상태가 불명확하면 조회부터 한다.

10:05 즉시 완화: `billing webhook retry`의 `webhook_attempts`를 이전 `7`에서 `3`로 조정한 canary를 비교했습니다. 재발 빈도와 영향 범위를 줄이기 위한 조치이며, 이것만으로 원인이 사라졌다고 보지 않습니다. 확정된 정책 계약은 아래 배운 점과 채택 결정에 있습니다.

후속 작업: TASK-BILL-21: 중복 수신 계수와 실제 청구 계수를 분리한다.

배운 점: 결제 webhook 재전송은 idempotency key로 중복 청구를 막는다. 알림 worker의 5회 재시도 정책을 복사하면 안 된다. [채택 결정](../decisions/decision-current.md).
