# 로컬 전환 점검과 실측 — 2026-09-09

**로컬 E5 전환은 보류했다.** 인덱싱 CPU와 메모리는 크게 줄었지만 평가 복제본의
전체 검색 p95가 수용 기준을 넘었고, 정답 검토·개인정보 거부·참조 보존 문제가
남아 있다. 운영 설정·설치본·DB 교체·공유 MCP 프로세스 재시작은 수행하지 않았다.

## 실제 설치 상태와 보완

측정 당시 기본 실행 파일은 설치된 `memtomem 0.5.0` / Python 3.13의 BGE-M3를 사용했다.
실효 설정은 1024차원, 모델 최대 길이 사용, 4스레드·배치 8·CPU arena 비활성화다.
설정 파일의 4096토큰 청크 예산은 이 구버전의 실효 설정에 반영되지 않는다.
리랭커 이름은 지정돼 있지만 `enabled=false`이므로 이번 운영 경로 측정도
리랭커를 켜지 않았다.

설치본은 스키마 1까지만 지원하지만 운영 DB 백업은 스키마 2다. **설치본으로
새 연결을 열면 `SchemaDowngradeError`가 발생한다.** 스키마 번호를 낮추거나
검사를 우회하지 않았다. 현재 실행 중인 오래된 연결이 있다는 사실은 새 연결의
호환성 증거가 아니다. 전환·복구용 코드와 DB의 스키마 호환성도 함께 확인해야 한다.

PR에는 다음 보완을 반영했다.

- 청크 감사·마이그레이션이 공통 tokenizer resolver의 체크섬을 사용하도록 수정.
  감사 CLI에 문맥·전체 입력 예산과 접두사 옵션 추가.
- `httpx2` / `httpcore2`를 2.12.0으로 갱신해 기존 의존성 보안 검사 실패 해결.
- Windows 타이머 정밀도에 의존하던 워처 테스트를 지속적인 이벤트 공급으로 수정.

코드 보완 커밋 `19d22353`의 Linux/macOS/Windows, 브라우저, 보안 CI는 통과했다.
이후 보고서·재현 도구 커밋의 CI 상태와 구분해야 한다. 로컬 전체 테스트는
15,146개 통과·372개 건너뜀, 마지막 관련 테스트는 23개 통과했다. mypy는
366개 소스 파일에서 오류가 없었다. 변경 범위 Ruff 포맷과 lint는 통과하며,
전체 포맷에는 수정하지 않은 `.github/cla-check.py`의 기존 위반이 남는다.

## 대표 파일 A/B/C 각 3회

동결한 원본 2,143개 중 개인정보 검사를 통과한 집합에서 파일 형식과 크기를
반영한 **동일한 63개 파일**을 선정했다. 매번 독립 프로세스와 빈 평가 DB를
사용하고 실험을 직렬 실행했다. 다운로드와 모델 초기 로딩은 인덱싱 시간에서
분리했다. 아래는 3회 중앙값이며, RSS는 전용 물리 메모리와 같지 않다.

| 조건 | 인덱싱 초 | CPU 누적 초 | 최대 RSS GiB | 청크 수 |
|---|---:|---:|---:|---:|
| A: 현재 설치본 + 실효 BGE 설정 | 87.49 | 346.48 | 8.46 | 238 |
| B: PR 코드 + 파일에 지정된 BGE 설정 | 144.68 | 519.90 | 17.16 | 268 |
| C: PR 코드 + E5-small FP32 기본값 | 14.66 | 27.56 | 1.88 | 478 |

C는 A보다 약 **5.97배 빠르고, CPU 시간 92.0%·최대 RSS 77.8% 감소**다.
B에서는 새 코드가 기존 설정 파일의 청크 예산을 적용하고 파싱 경로도 달라진다.
따라서 A→B는 동일 바이너리에서 모델만 바꾼 비교가 아니다. **BGE를 유지한 채
코드만 업데이트하면 부하도 줄 것이라고 가정할 수 없다.** 모델만 비교한 고정
입력 실험은 [이전 보고서](REPORT.ko.md)에 별도로 있다.

최초 실패한 구성 로딩과 범위 축소 시 중단한 불완전 실행은 집계에 포함하지
않았다. 완료된 반복 결과는 재사용했으며, 사용자 요청에 따라 전체 A/B 재색인은
실행하지 않았다. 일반 데스크톱의 다른 프로세스에 따른 변동은 남는다.

## 전체 E5 1회와 무결성

- 개인정보 검사 거부 5개를 제외한 **2,138개 파일 → 18,163개 청크**.
- 인덱싱 **591.12초**, CPU **1,099.20초**, 최대 RSS **2.33GiB**.
- 무변경 재실행 **18.98초**, 재임베딩 **0개**.
- 청크·벡터·FTS 각각 18,163개, 누락 0개, 완료 영수증 2,138개.
- 접두사·문맥 포함 실제 최대 입력 **484토큰**, 512토큰 초과 0개.
- SQLite `quick_check=ok`, 외래 키 오류 0개.

이 DB는 **신규 평가 색인**이다. 원래 DB의 namespace 메타데이터·공유 링크·세션
이력을 이관한 운영 교체본이 아니다. 원본 메타데이터의 보존을 증명하려면 별도의
마이그레이션과 참조 검증이 필요하다. 측정 중 원본 6개의 해시가 스냅샷과 달라져,
나중에 전환하더라도 최종 변경분을 다시 확인해야 한다.

## 실제 질의 100건 × 3회

한국어 40·영어 40·혼합 20건이다. 경로 형태의 자동 질의가 중요 질의 목록을
독점하지 않도록 언어별 표본의 최대 1/4로 제한하고, 중요 후보 20건은 사용자
검토 대상으로 남겼다. **독립 정답이 확정되지 않아 nDCG·Recall을 계산하지 않았다.**

설치본 A는 스키마 문제로 기존 DB 복제본을 열지 못한다. 아래 B는 **호환되는
PR 코드로 기존 BGE 벡터를 조회**한 결과다. C는 전체 E5 평가 색인을 사용하고,
복사 경로에 붙은 실험 디렉터리 접두사는 검색용 복제본에서 제거했다. 두 DB는
청크·메타데이터·개인정보 제외 범위가 달라 순수한 모델 품질 비교가 아니다.

| 경로 | 기존 BGE p50 / p95 ms | E5 평가 색인 p50 / p95 ms |
|---|---:|---:|
| Dense: 임베딩 + 벡터 조회 | 41.47 / 83.13 | 12.87 / 17.85 |
| 운영 검색: 캐시 미적중 | 49.78 / 130.18 | 24.79 / 182.26 |
| 운영 검색: 캐시 적중 | 0.83 / 0.97 | 0.91 / 1.05 |

실제 캐시 경로에서 양쪽 **300/300회 적중**을 확인했다. 최초 고정 시점 재생은
`as_of_unix`가 캐시를 우회해 적중이 0회였으므로 캐시 성능 근거에서 제외했다.

캐시 미적중 p95는 **약 40.0% 악화**해 합의한 10% 이내 기준을 통과하지 못했다.
E5의 느린 질의에서는 BM25 대기 시간이 약 167–217ms, 벡터 조회는 약 7ms였다.
늘어난 청크와 FTS 후보 탐색 비용이 주요 원인으로 보이지만, 메타데이터가 보존된
운영 마이그레이션 결과에 대한 확정 인과 분석은 아니다. 비동기 구간 시간에는
이벤트 루프 대기가 포함되고 서로 겹치므로 단계 시간을 합산하면 안 된다.

## 실제 파일 이벤트와 전환 조건

실제 파일을 동일 바이트로 20회 쓰고, 설정된 observer로 1개·3개 프로세스의
처리를 측정했다. macOS의 `auto`는 polling이다. 빈 DB를 3개 구버전 프로세스가
동시에 처음 열 때 WAL 초기화 잠금 오류가 발생한 실험은 따로 남겼다. 최종 비교는
스키마를 한 번 준비한 뒤 진행한 **기존 DB의 워처 동작**이다.

| 조건 | 프로세스 수 | 청크 계산 호출 | 임베딩 호출 |
|---|---:|---:|---:|
| A | 1 / 3 | 1 / 3 | 1 / 1 |
| B | 1 / 3 | 1 / 1 | 1 / 1 |
| C | 1 / 3 | 1 / 1 | 1 / 1 |

기존 구현도 이 실험에서는 중복 벡터 계산을 피했다. 새 영수증은 대기 프로세스의
불필요한 **청크 계산**을 줄였다. 이 결과로 과거 고부하가 동일 세대의 중복
임베딩이었다고 단정할 수 없다. 작은 파일의 다중 프로세스 실험에서는 토크나이저
초기화 비용도 존재하므로 단일 대량 인덱싱의 RSS 감소율을 그대로 적용할 수 없다.
프로세스 트리 RSS 집계는 실험 관리자와 공유 페이지도 포함한다.

현재 전환 조건은 다음과 같다.

- **성능:** 대표 인덱싱 CPU/RSS 개선. 전체 검색 p95 기준 미달.
- **품질:** 중요 질의 20건과 전체 100건의 독립 정답 검토 미완료.
- **데이터:** 개인정보 거부 5개. 공유 링크 7개 중 6개는 동일 본문 해시로 유일한
  새 청크에 대응하지 않아 추가 참조 검토가 필요하다. 이를 삭제·우회하지 않았다.
- **배포/복구:** 구버전 실행 파일과 스키마 2 DB의 호환 문제 해결 필요.
  평가 DB를 운영 DB로 교체하지 않았으며 실제 전환·복구·30분 관찰은 미실행이다.

원문·질의·참조 검토 자료는 비공개 로컬 스냅샷에만 보관한다.
[공개 가능한 집계 JSON](mac-arm64-local-transition-results.json)에 반복별 수치,
라이브러리·구현 해시, 실험 한계와 보류 조건을 기록했다.

## 후속 로컬 전환 — 사용자 수용 후

사용자가 측정된 품질·지연 차이를 수용하고 E5-small 전환 및 거부된 5개 파일의
색인용 마스킹을 승인했다. 앞 절의 HOLD는 승인 전 판정이다. 새 운영 백업에서
별도로 이관했으며 평가용 빈 DB를 운영 DB 위에 덮어쓰지 않았다.

- 원본 2,145개 파일 → 18,265개 청크·벡터·FTS. 최종 입력 최대 484토큰.
- 동일 모델 설정과 동일 입력 해시가 일치하는 E5 벡터 18,133개 재사용,
  변경·마스킹·기존 링크 청크 132개 새로 임베딩.
- 5개 파일의 파서로 확인한 전체 블록을 마스킹했다. 원본은 수정하지 않았다.
  검토 manifest는 정확한 경로·본문 SHA-256·행 범위에 한정된다. 원본 변경,
  잘못된 manifest 또는 남은 개인정보 패턴은 정상 거부 경로로 돌아간다.
  전역 자동 마스킹은 여전히 비활성화다. 마스킹 청크는 읽기 전용이며
  원본 수정 권한을 부여하는 span hash를 갖지 않는다.
- 링크 7개와 연결 청크 ID를 보존했다. 혼합 namespace는 별도 그룹으로 이관했다.
  namespace 메타데이터, 세션, 이벤트, 검색 이력, 평가 자료는 행 단위로 동일하다.
  namespace/scope/태그/유효 기간도 별도로 비교했다. 원본 해시 변경 0개.
- 새 설치본에서 E5 384차원, 입력 제한 512토큰, 2스레드와 실제 dense/hybrid
  검색 성공을 확인했다. 정확히 512토큰은 성공하고 513토큰은 거부한다.
- 이후 재색인이 연결된 청크 ID를 삭제하려 하면 트랜잭션을 거부하도록 보완했다.
  파일을 삭제하는 별도 작업의 의미를 바꾸는 것은 아니다.

기존 설정·설치본·BGE DB를 복구용으로 보관했다. 이전 설치본의 스키마 호환성
문제가 있으므로 새 연결의 BGE 복구에는 스키마 2를 지원하는 코드도 필요하다.
기존 MCP stdio 연결은 종료되었으므로 클라이언트에서 재연결해야 한다.
이 전환은 독립 정답 평가가 완료됐다는 뜻이 아니며, 기존 nDCG/Recall의 한계는
그대로 남는다.
