# memtomem for Antigravity CLI

> **Experimental** — this plugin is new in memtomem 0.7.0, so its layout and
> skills can change without a deprecation window. See
> [Stability](https://github.com/memtomem/memtomem#stability).

Markdown-first long-term memory shared across your coding agents. This plugin starts a
local memtomem MCP server in the Antigravity CLI (`agy`) and adds nine memory workflow
skills. Notes saved here are searchable from Claude Code, Codex CLI, Kimi Code and any
other client that uses the same `~/.memtomem` store.

`mcp_config.json`, `plugin.json` and `skills/` are generated by
`tools/render_plugin_assets.py` from `packages/memtomem-plugin-assets/`; edit the sources
there, not the files here.

## Requirements

- Antigravity CLI (`agy`) 1.4.7 or later, the version this plugin was verified against.
- `uv` on `PATH`. The server is started with
  `uvx --python 3.12 --from 'memtomem[onnx]==0.7.2' memtomem-server`.
- Python 3.12. uv uses a 3.12 it can find; if there is none, it downloads one (about
  70 MiB) on first start. If that is not possible — offline, or uv's Python downloads
  turned off — the server does not start; run `uv python install 3.12` once to fix it.

## Install

Install straight from this repository:

```bash
agy plugin install https://github.com/memtomem/memtomem/tree/main/packages/memtomem-antigravity-plugin
```

or from a local clone:

```bash
agy plugin install /path/to/memtomem/packages/memtomem-antigravity-plugin
```

The plugin is copied to `~/.gemini/config/plugins/memtomem`. Installing does not start
the server; start a new `agy` session to load it. `main` normally pins a published
memtomem release, but right after a version bump is merged it can pin one that is not on
[PyPI](https://pypi.org/project/memtomem/#history) yet, and the server then fails to
start until it is.

To update, reinstall: `agy plugin uninstall memtomem`, then run the install command
again. `agy plugin uninstall memtomem` also removes the plugin; your memories stay in
`~/.memtomem`.

**If you already registered memtomem by hand** (for example with
`agy mcp add memtomem memtomem-server`, which writes `~/.gemini/config/mcp_config.json`),
both servers run side by side: agy names the plugin's server `memtomem_memtomem`, so it
does not replace your entry. Remove the hand-written one with `agy mcp remove memtomem`
to keep a single server. To keep your manual registration and retain the plugin's
nine skills instead, use the source-checkout
[skills-only reconciliation](../../docs/guides/mcp-clients.md#keep-manual-mcp-and-plugin-skills).
It suppresses only the bundled MCP entry; plugin updates can restore that entry, so
rerun the diagnostic after reinstalling. The manual server retains its existing
working-directory behavior.

## First run

No separate setup is needed: on a machine where memtomem has never been configured, the
server uses its defaults (SQLite store in `~/.memtomem/memtomem.db`, notes in
`~/.memtomem/memories`, BM25 search). If memtomem is already set up for your other agents
through `~/.memtomem/config.json`, the server reads that configuration and shares the
same store — provided the storage and memory paths in it are absolute or start with `~`.
A relative path resolves against this server's working directory (the plugin directory),
so it would open a different store. Ask the agent for memtomem status and check the
reported DB path before relying on sharing.

## Scope

agy starts the server in the plugin directory, and memtomem takes its project context from
the directory its server starts in, so the server begins at **user scope**. Six skills
(search, recall, remember, index, status, setup) work there: notes are shared with your
other agents through the user-scope store, `remember` writes user-scope memory only, and
paths given to indexing must be absolute.

The three project workflows (`memtomem-handoff`, `memtomem-brief`, `memtomem-update`)
first bind the server to the repository you are working in (`mem_project_bind`, through
`mem_do`), then use its `project_local` tier. They need:

- a registered tier in that repository: `cd <repo> && mm mem init --scope project_local`;
- a server that is not yet bound to another repository. A binding lasts until the memtomem
  server process restarts, so working in a second repository needs that restart first.

After a binding, search and recall in that server process also see the bound repository's
project tiers. The skills-only setup above, whose manual server already starts in your
workspace, binds the same way.

## Network

Memory is stored locally in `~/.memtomem`. The server is downloaded from PyPI on first
start, and uv downloads Python 3.12 then too if it cannot find one. With a fresh
BM25-only configuration nothing else leaves the machine. An existing memtomem
configuration may enable its own network paths: model downloads from Hugging Face (ONNX
embedding or local reranker), a remote embedding or LLM provider, Cohere reranking
(sends the query and candidate chunks), or search webhooks (send events including the
query).
